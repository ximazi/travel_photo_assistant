旅行人物摄影助手：最小评测协议
版本：0.1.0
状态：设计方案与待执行案例；尚未开展模型评测、现场实验或统计验证。

一、评测目标

最终目标是：让普通用户在既定设备与现场约束下，更容易拍出符合其个人意图的旅行人像。
必须分别检查：观察是否正确、指导是否可执行、最终照片是否改善。
场景分类准确率、遵守三分法的比例、模型自报美感分数，均不能替代成片改善证据。

二、待比较方案

A：同一视觉语言模型 + 明确任务提示词。
B：A + 少量人工精选且始终注入的摄影规则。
C：A + 根据当前视觉条件、用户目标、设备和约束检索的摄影方案卡片。
现场实验另设无指导拍摄基线。

固定模型版本、提示词版本、图像分辨率、输入帧、设备信息和输出协议。
B、C 尽量匹配注入文本量，并记录检索耗时，避免把内容数量的差异误认为检索效果。
对 C 区分：检索错误、知识卡前提判断错误、检索正确但规划错误。
上述方案只作为待测试设计，不代表任何一组已证实更好。

三、分层指标

1. 观察层
检查关键视觉事实是否有证据，包括人物是否存在、遮挡、背景线条、主要景物及光线关系。
记录错误事实率、关键问题漏检率、模型把未知描述成已知的次数。
对存在人工标注的位置数据，可记录归一化坐标误差；位置误差不能自行等同于照片美感。

2. 执行层
记录用户无需额外解释的完成率、完成耗时、反复纠正次数，以及镜头或功能不可用的建议次数。
检查指令是否明确操作主体、动作类型、参考方向和停止条件。
需要现场确认的动作，应先完成确认，再给移动步骤；不得把确认要求隐藏在长段文字后。

3. 成片层
目标用户与摄影人员分别盲评成片，隐藏方案名称并随机左右顺序。
评价问题应体现本次目标，例如：哪张更符合“环境清楚、人物自然、能看出旅行地点”？
允许“平局”“两张都不喜欢”，报告这些选项的比例。
记录偏好率、可接受成片比例、用户满意度和每张满意照片所需时间。
模型自评分只能用作诊断信号，不作为唯一裁判，也不直接作为自训练标签。

4. 实时体验层
测量真实端到端延迟的分布、旧响应被误用的次数、提示来回反转的次数及耗电表现。
不预先把任何延迟或准确率写成已达到的能力。

四、数据与现场安排

可以先策划约 30 个任务作为小规模试点，不据此自动宣称统计显著性或总体性能。
任务覆盖海边、山林、城市，以及逆光、光向不明、杂乱背景、弱光、空间受限等条件。
每项记录：任务标识、初始画面、用户目标、设备能力、现场约束、模型与提示词版本、知识卡标识、建议、实际动作、后续画面、最终照片和用户反馈。
现场对照尽量固定地点、人物与光线，并交错安排方案顺序，减少熟练度和光线变化的干扰。
离线评测用于事实、硬件能力、规则适用性和指令检查；是否改善成片需要现场执行或真实用户数据验证。
知识库与验证集按地点或拍摄会话隔离，避免相邻帧、同一案例或其改写泄漏。
后续报告应给出样本数量、任务构成、平局比例和不确定性，不能只给一个总分。

五、物理动作语义：必须检查

相机转动：保持相机光心位置基本不变，改变朝向和取景范围。
相机平移：拍摄者实际移动相机光心，可能产生前后景视差。
人物移动：被摄者在现场改变位置，能改变其与背景的相对关系。
变焦或裁切：改变视野和画面占比，本身不等同于改变相机位置。

纯转动手机、移动裁切框或同机位变焦，通常不能消除同一视线上的人物与电线杆重叠。
不能因为人物被移到画面左侧，就宣称其与背景重叠已解决。
要消除重叠，通常需要人物位移或相机实际平移，并用新画面验证结果。
单帧缺少可靠空间关系时，不能保证拍摄者向哪一边移动、移动多少就必然成功。
若允许且现场可行，可提出小幅试探动作；必须观察新画面，改善后停止，变差则取消或重新规划。
镜头长短对取景有影响；不能把只换焦距直接描述为已经改变透视关系。

六、每条指导的最小合同

操作主体：拍摄者 / 被摄者 / 相机功能。
动作类型：相机转动 / 相机平移 / 人物移动 / 姿态变化 / 变焦 / 曝光或对焦操作。
依据：引用当前画面的可见证据或已提供的设备与约束信息。
参考方向：明确是画面方向、拍摄者方向还是被摄者自身方向。
停止条件：以能观察到的结果描述，不虚构米数或角度精度。
再验证项：说明执行后需要重新检查的视觉关系。

界面每次只突出一条当前动作；其他动作作为后续步骤。
不要同时改变机位、人物站位和焦距后，仍声称能够判断单个动作的效果。
所有归一化坐标需经过输入旋转、预览裁切、缩放和镜像转换，才能成为屏幕上的箭头或框。

七、知识卡适用性检查

每张知识卡应具有：适用条件、不适用条件、必要视觉证据、设备要求、移动空间要求、预期改善、失败表现、替代方案和版本。
检索命中不代表必须采用；前提不满足时应拒用，并指出缺失的条件。
记录实际采用的卡片标识与满足的前提，避免只按“海边”“城市”等标签机械匹配。
风格规则通常是软偏好；设备不可用、画面未观察到、未知空间可通行性属于约束，不能靠风格分数覆盖。

八、状态与过期规则

响应需要绑定输入帧、场景或拍摄会话、镜头与画幅、用户目标以及当前计划版本。
明显转向、换镜头、改变目标、人物离开或新人物加入时，应检查是否需要重规划。
过期响应不得覆盖新计划。
用户正在执行已接受方案时，轻微抖动不能触发风格或左右方向反复切换。
锁定计划不意味着忽略重大环境变化：前提失效时应停止旧动作，并说明需要重新观察。

九、执行结果记录方式

evaluation_cases.json 是待执行案例集，没有包含任何已通过结果。
实际执行时，另建结果记录，包含 case_id、输入资产、模型版本、输出原文、人工判定、失败类型和备注。
不要回填虚构的运行结果；没有执行的案例保留“未执行”。
先修复硬件幻觉、坐标反向、过期计划和不可执行动作等明确问题，再比较风格与成片偏好。

十、分期建议

阶段 1：静态输入，对照 A/B/C，确定事实输出和行动协议。
阶段 2：用户执行一步后重新观察，形成真实“初始条件—动作—结果”案例。
阶段 3：加入端侧跟踪、计划锁定、过期取消和实时体验测量。
阶段 4：只有发现提示词与检索难以稳定解决的问题，并积累可靠结果标签后，再评估微调。

长期应积累可验证的拍摄改善案例，而不是仅积累漂亮照片或模型自写评价。
