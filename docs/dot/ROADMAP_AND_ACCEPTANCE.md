# Dot 推进计划与阶段验收 v1.0

## 当前实际基线（只读仓库初审，未运行实测）
- main 现有 Python backend v0.1；observation+planning 分离，慢语义/快对齐控制器、校验、坐标映射、知识卡检索、真实 VLM adapters（OpenAI/Gemini/Qwen）、CLI/HTTP API、图片渲染和单元测试。
- README 声明 9 张知识卡和 E01–E16 离线契约用例，评测协议标明 field_photo_status=not_executed；本轮未在手机端运行、未调用真实付费视觉模型、未验证单元测试通过率。
- 仓库根目录未看到 Android/iOS 原生端目录；有模拟/离线渲染，不能等同于真实 camera preview 引导。

## P0：基线审计（必须先做）
任务：列出全部模块职责、代码质量、安全问题、接口/时序一致性、可运行性、测试缺口、缺失手机端和服务端闭环；核对文档声明与真实行为。运行现有测试，给出真实执行命令与结果，保留失败日志。
交付：docs/audit/CURRENT_STATE.md、docs/audit/GAP_MATRIX.md、docs/audit/BASELINE_RESULTS.md；优先级 P0/P1/P2；每项指向可验证代码/失败示例。
验收：不写“已完成”而无命令/日志/设备证据；输出明确下一阶段可开发 issue；冻结可复现的主干基线 commit。

## P1：真实照片“诊断→改善建议”能力
范围：10–30 张授权真实旅行人物照/空镜，海边、树林、街道、地标、夜景；带人工关键事实标签及限制条件。测试真实 VLM 和当前三种 A prompt-only/B fixed cards/C retrieved cards。对每张图输出 observation.json、plan.json、overlay 及证据说明。
必修：不得从环境标签机械推出动作；无人物时建议站位但不虚构已有主体；有人物时检查背景压头、切脚、人物比例、水平线、脸部明暗。展示“原画面→观察事实→建议动作→预期改善”。
验收：分层报告事实错误、关键问题漏检、不可执行建议、未知推断、成本/耗时；至少 5 个完整人工审阅的成功样本和失败样本；不能把 schema pass 当成照片质量。
此阶段不自动宣称 30 张数据有统计显著性。

## P2：可操作手机 MVP（一个平台优先）
至少交付：真实 CameraX 或 AVFoundation 预览与拍照、镜头元数据、选择目标、抓取分析帧、服务请求、目标虚框/箭头/参照线叠加、过期回复丢弃、取景新帧校正、离线拍摄降级。
验收：在真实手机上展示海边/街道或可替代同类场景，完整“构图建议→执行→确认→拍照”视频及日志；非 mock 服务可运行；云端失败不阻断原生快门；手机转向/镜头切换不会残留旧指引。

## P3：实时端侧反馈与姿态指导
端侧检测/追踪人体关键点、人物框、方向；与已锁定目标比对，稳定防抖（不要每帧推翻建议），指导机位→人物站位→肩身→手→视线；必要时重新云端观察。
验收：真实设备连续运动时提示稳定，不发生明显左右镜像错误；重复提示/建议反转/过期覆盖可量化；明显不安全指令必须被拦截。

## P4：摄影质量实验与策略迭代
设无指导基线 + A/B/C，控制人物/地点/天气光照时间、顺序交错。用户/摄影师盲评旅行信息、人像自然度、背景杂物、偏好、满意成片耗时。
验收：出具原片对照、匿名评审与原始记录、失败类型归因；优先修复观察错误→指令错误→执行反馈错误；没有优势就修改/简化知识库而非强行保留。
持续优化仅保留经过留出场景验证的有效变更。

## 每个任务的 Definition of Done
1. User story + 失败输入 + 预期行为 + 失效/回退条件；
2. 代码/文档/真实样例 + 自动测试 + 操作复现步骤；
3. 贴实际执行环境、测试日志、相关截图或结果图；
4. 评估对“观察正确→动作可执行→成片改善”的影响；
5. 独立分支 PR，标记待用户合并，不自动更改 main。

## 当前第一批 Issue 方向
- A1：代码和协议审计；运行测试与记录可信基线
- A2：构建有人工标注的旅行人物摄影基准集与失败分类
- A3：真实 VLM 端到端观测/规划质量对照与成本基线
- A4：移动端 MVP 选型与摄像头 Overlay 协议
- A5：面向用户的分步指令和终止条件契约
- A6：真实手机实测 + 初始无指导对照

指标阈值须先做试点得到基线后提出、经用户审阅锁定；禁止凭空宣称已达到。
