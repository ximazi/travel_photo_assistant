# 旅行摄影评分：人数盲评小样本协议 v0.1

关联 #31 / Draft #32。只校准“画面恰好一人”这类硬性事实要求，不评价人物是否突出、成片是否好看，不验证助手能否改善成片。

## 盲评和冻结

1. 先用六张新实拍做标注流程试点，不纳入已有 DEV-02，也不按社交热度选样本。众多场景或干扰物等覆盖不足时继续扩充。正式盲测按拍摄地点、拍摄组和来源与开发集切分；地点或拍摄组相关的照片不能当独立样本。当前小样本不具发布验收效力。
2. 操作员用同一版本图像解码：按 EXIF 方向转正、RGB、全画幅不裁剪、长边 ≤1200px、Lanczos、JPEG quality 92、去 EXIF。保存来源、权利、拍摄组、处理版本、SHA-256 与编号映射，仅操作员可见。盲评员只看中性编号和相同图像字节，不看描述、来源、其他评审或模型输出。不得用原图、AI 放大或上网回查判答案。
3. 两位真人独立标注每图：`zero`（可读且没有真实人）、`one`（可读且恰一人）、`multiple`（至少两处证实为不同的人，即使还有可疑候选）、`uncertain`（只确认一人或零人但尚有可能出现人物的不可判区域）。写出确认人物位置和最关键的排除或不确定区域；只计真实可见人物，不把镜像、海报、雕像、岩石和同一个人不同身体部分算作额外人物。纯天空/水面等无合理人物线索的模糊区域不自动导致未知；合理人形线索或人可站立的遮挡区域才写明。人物是否醒目另记，不影响计数。两人不一致保留分歧，不求平均，不用模型仲裁。投票原始记录保留在授权范围内。
4. 在任何候选或基线模型推理前，将图像哈希、A/B 分组和两票写进锁定面板并计算面板 SHA。模型不得看到标签、出处、老结果、样本类别或预期数量。已有开发集不能重命名进入正式盲测。素材即使可合法使用，也必须单独确认给云模型的分享权限；未经允许、权利冲突或身份有疑虑时仅本地使用。跨模型比较只能使用双方均获授权的交集；禁用付费调用，不为覆盖率补发失败请求。

## 可复现计分

调用 `python scripts/compare_people_panels.py panel.json submissions.json`。格式示意如下，`<...>` 是需替换的值：

```json
{"version":"people-panel-v0.1","pairs":{"pair01":{"A":{"sha256":"<64 lowercase hex>","votes":["one","one"]},"B":{"sha256":"<64 lowercase hex>","votes":["multiple","uncertain"]}}}}
```

```json
{"<pinned provider/model/config>":{"panel_sha256":"<hash of untouched panel bytes>","pairs":{"pair01":{"forward":{"image_sha256":["<A hash>","<B hash>"],"receipt":{"version":"people-enumeration-v0.1","A":{},"B":{}}},"reverse":null}}}}
```

每个有回复的顺序用未经改写的原始 JSON 对象替换 `receipt`；缺失或无法解析、检测到重复键、被截断的顺序保留为 null 并在原始回执记录原因。示例中的空图像对象不是可用回执。提交时提供已核验的实际发送字节哈希；反序必须 B 在前，不接受不同面板或不同图片。模型与传输配置单独锁定和记录。

首要错误指标是人评确定为非单人时，**任一顺序**误放行的图片数 / 人评确定非单人图片数，避免换序汇总把一次误判藏起来。同时报告稳定误放行、真人单人稳定通过、误拒、顺序冲突、未知和无效。未知不是通过；真人不确定与分歧不进入正确率分母，但保留各自样本量。零分母不代表零错误。结果小样本只报分子分母，不据此宣布胜者；“全未知”会体现为低通过覆盖。完整曝光（图片是否好看）用五维标注体系另测。

**验证**：新增 5 个离线用例，相关套件 35/35 通过，覆盖换序、一次误放行、未知与失败分离、分歧样本分母以及锁定对象不匹配。本轮未收真人分票，也未对新的候选批次跑模型。只有合规且双票冻结后才汇报双模型盲测。
