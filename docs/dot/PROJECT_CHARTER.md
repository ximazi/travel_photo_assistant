# Travel Photo Assistant — Dot 项目章程 v1.0

## 0. 项目目标（不得降级）
打造面向普通游客的**人物旅行摄影教练**，而非场景标签识别器、摄影知识问答机器人、图片美学打分器或照片生成器。

用户面对海边、山林、城市街道、建筑、山峰、湖泊、夜景等真实场景，以**人物+旅行记忆点**为主要成片目标。系统必须从真实取景图与用户意图出发，指出**当前画面有什么、哪里不好、怎样通过可执行的一两个动作改善**，并在用户执行后检查是否改善，最终用真实成片与无指导基线验证价值。

## 1. 用户闭环 / User Journey
1. 选择目标（人物优先 / 人景兼顾 / 地标+人物；风格：自然、氛围、街拍、纪念等）及拍摄方式（摄影师拍/自拍；全身/半身）。
2. 手机相机取景，读取当前镜头、等效焦距/视角、方向、裁切、镜像等真实能力。
3. 场景观察：人（或空镜）、背景/地标/引导线/对称结构、遮挡与杂物、脸部光线、环境安全未知项；每个重要判断有画面证据及坐标。
4. 产出最多 1 个主方案、必要时 1 个备选，明确 **摄影师/被拍者**、动作、方向、幅度/边界、原因、成功判据。
5. 端上叠加人物目标位置/地平线/参考锚点。先指导**机位→构图→人物站位→姿态→视线**，每次只推进当前最重要的一步。
6. 用户调整后，通过本地快速追踪和必要时新的云端观察核查；完成后提示快门，成片保存在手机端。
7. 拍后用户可选成片对照/评价；不自动修脸、不自动生成虚假旅行照片、不自动改用户人物画像或资料。

## 2. 必须延续当前仓库的设计约束
- 复用已存在的 Python observation→retrieval→planning→validation→controller，JSON Schema、坐标变换与测试；先审计、再重构，不以重写为默认。
- 云端 **慢语义循环**：针对低频关键场景帧调用 VLM，不上传每一帧。端侧 **快对齐循环**：本地人物追踪/骨架/地平线/目标框/镜头状态反馈。
- 有图才能做现场判断；禁止编造人物、地标、光线方向、可达空间与物理距离。只有证据才能解释建议；允许“无法判断/不用调整”。
- 焦距建议以可用手机物理镜头及实际画幅为准；35mm 等效焦距是提示而非图像可测事实，不能要求不存在的镜头。
- 人物与摄影者的动作要区分；移动至道路、水边、悬崖或未知地面前必须先确认安全与可达性。摄影建议不应妨碍拍摄/阻塞快门。
- 尊重原图真实感与自主决定；禁止对人物身体做评分。多人时先选定主体。
- 旧规划需要关联 frame_id、scene_version、goal_version；过期回复不得覆盖新取景。
- 规则检索是辅助，不得把三分法等当作唯一正确答案。

## 3. 产品与研发架构（目标而非宣称已实现）
CameraX/AVFoundation 原生摄像头+端侧视觉（例如 MediaPipe Pose） → 稀疏真实帧/设备元数据 → Scene Observer(VLM) → 检索适用摄影知识卡 → Shot Planner(VLM) → Schema+业务+设备+安全校验 → 结构化 ShotPlan → 端上 Overlay/动作指导 → 重取景与验证 → 用户拍照与可选反馈。
服务端优先沿用当前 Python 项目，可基于 FastAPI，服务提供商置于 adapters 后。手机 Android/iOS 是否双端同期交付，以技术审计与 MVP 验证后的优先级决定；不得把 CLI demo 当作手机体验完成。

## 4. 产品成功的三个硬门槛
- **观察正确**：影响方案的关键事实（人物是否存在、头部背景重叠、地标/引导线、脸部明暗、可见地面）不能明显造假，错误/未知有追踪与纠正机制。
- **建议可执行**：普通人按提示可以明确知道谁、做什么、朝哪边、做到何时；不会推荐不存在镜头、危险站位或与目标相冲突的动作。
- **成片真实改善**：同地点、同人、接近同光线，和无指导及简单提示词基线比较，盲评偏好和满意成片所需时间有证据。只有 JSON 有效、测试通过不等于产品目标达成。

## 5. 角色分工
- Dot = 产品负责人/研究协调/验收审计/任务推进；维护目标、差距、实验、风险、阶段与决策。
- Codex = 分支内代码开发/自动测试/修复/提交 Draft PR。
- Windows Worker = 用户明确授权时本地运行、手机实机联调辅助、评测执行；不可假设已在线。
- 用户 = 产品目标、优先级、设备和真实用户照片/现场试验、涉及合并/上线/费用的审批。

## 6. 权限
可自主：只读审计、调研、设计文档、创建 Issue、在独立分支编码、单测、创建 Draft PR、离线实验、形成评审报告。
必须用户确认：合入 main、上线生产、对外分享私密影像、购买/调用付费模型或超预算试验、删除不可逆资源。照片需遵守授权、最少上传、脱敏和明确保留期限；密钥只留在本地环境变量/secret store。

## 7. 拒绝的伪进展
- 使用 mock 结果宣称真实视觉效果；拿 Schema 合格率冒充摄影能力；
- 只增加 Prompt 字数或摄影卡片数量，却无实际成片改善；
- 用模型自评当人工成片偏好；只提交漂亮的静态演示图；
- 把不具备证据的“移动 2 米/转向 30 度/换 85mm”说成现场必然可行；
- 没有用户允许就合并/发布/消耗付费配额。
