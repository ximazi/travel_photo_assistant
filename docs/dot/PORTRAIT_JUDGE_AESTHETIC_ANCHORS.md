**不晋级。** 构图、光色、姿态的 4 分改成「指出关系及其额外效果」，但只增加文字要求未改善这两组实图。间歇泉的换序分差消失，是因为四次出分都到 100（两张照片 × 两种顺序），不是辨别力变好。海岸仍随顺序从明确首选变成平局。保留默认版本。

## 可复核设计

以 [v0.4 观察实验](PORTRAIT_JUDGE_OBSERVATION_EXPERIMENT.md) 为基线，仅改 [候选提示词](../../assets/prompts/portrait_quality_review.anchor_experiment.system.txt) 中 composition、light_color、pose_story 的 3–4 档。结果版本字段沿用 v0.4 **仅表示兼容的 JSON 结构**；区分实验以提示词 SHA 为准。人景关系、技术、资格、意图、schema、权重、5 分判平不变。沿用 [DEV-02 海岸](PORTRAIT_JUDGE_DEV02_COAST.md) 与 [DEV-04 间歇泉](PORTRAIT_JUDGE_DEV04_OLD_FAITHFUL.md) 同一批处理图 SHA；本地 Qwen3-VL 4B Q4，清单 digest `84f7ed8042fa7cdbd902f7dcb7d0370e032095047cc3244179f263b77b5bc318`，温度 0、上下文 8192、最大输出 3000。每对、每顺序、每提示词各一次，正序旧→新，反序新→旧，无重试；8/8 正常停止并通过 schema 和裁决。两对熟悉开发样本，不是广泛代表、独立人评或重拍，无外部推理。

提示词 SHA-256（LF、单换行）：基线 `5b5a71ddfc624683ff044181aa27a3c5421e9062a2965aea937aacc611ca13f8`，候选 `c1ad6701ff1b9669984b98c171258ec60c221e166a4a5666b438cb28425da9a4`。正反槽位图片 SHA 单独记录。固定 schema 解析后按键排序的 Python JSON UTF-8 SHA-256：`87682139bca21f22cc7d70075bf2e1cd51204a6878b8cbfd4b6e49578fc3f3b0`。固定用户消息从 `'intent: ' + json.dumps(brief, ensure_ascii=False) + '\nAttachment order: first is A, second is B.'` 生成；间歇泉 SHA `4ec3a73fa304d00cad82a18582aee86d0d28ecb26e8f78590840de9b8929a726`，海岸 SHA `87b39841d470236505055969ebb92f3faa0d6d164b5956d72bb2e9a5c677e409`。

## 结果（按来源，不是附件槽位）

| 开发组 | 旧 A:B 正 / 反 | 新 A:B 正 / 反 | 三目标维度给 4 的次数，旧 → 新 |
| --- | --- | --- | --- |
| DEV-04 间歇泉 | 95:100 / 100:100；两次平 | 100:100 / 100:100；两次平 | 11/12 → 12/12 |
| DEV-02 海岸 | 90:72.5 / 72.5:72.5；A / 平 | 95:72.5 / 77.5:77.5；A / 平 | 1/12 → 2/12 |

- 具体查图：间歇泉剪影的右侧，手机与持机的手对浅色背景有可辨轮廓；候选给光色 4 时两个顺序主要写了强逆光、喷发尺度和深色人物，定位只说“center”，没说手与手机如何凭局部反差把动作读出来。存在可核对的局部关系，但这不是评委投出的 4 分，也不能宣称该光色一定只值 3。
- 海岸两图的分差随顺序从 17.5 分变成 0 的现象仍在；候选正序分差为 22.5、反序为 0。只改美感描述，海岸意图也由两次平变为正序 A、反序平。这次正序多人 B 的意图 1 不是「恰好一人」已被正确判为硬失败。
- 还有语言回归：候选四次响应的 40 条维度证据均无汉字、呈英文，基线 40 条均有汉字。结构有效不等于中文约束通过。无人工依据时不标「错误满分」或「正确满分」；只报告分档和证据观察。
- Windows 离线测试 52/52；未变更默认 prompt 和裁决。六图人数盲评未推理，无独立美感标签、无真实指导重拍。

## 下一次校准怎样验收

不要以「满分变少」「换序更稳」单独验收。全给 3 或全给 4 都能刷到稳定。每个目标维度先准备不同来源的开发照片，覆盖「有效的 3」和「有可核实增益的 4」，包括至少一张有意居中、一张背光剪影，以及有明确短板的照片。社媒点赞不算等级，构图好也不代表姿态应拿 4。与六图人数盲评和正式美感留出分开。

| 维度 | 3：清楚有效 | 4：额外可见效果 |
| --- | --- | --- |
| 构图 | 主次清楚，边缘取舍无明显干扰 | 可指出两个或以上可见锚点的空间关系，并说明它把注意力引向哪里、删去会损失什么。例如左右地形围住居中的旅人，仍留出通往远处地标的通道；不是仅凭「居中」得 4。 |
| 光色 | 主体或氛围可读，光色合适 | 可指出局部明暗/色彩关系及其效果。例如手和横持手机在亮背景上轮廓分开，使「拍摄」而非仅「站在那」一眼可读。不是脸亮才好，也不是只要有逆光就给 4。 |
| 姿态 | 人在做什么可读，动作自然且适合场景 | 可指出动作、朝向与画面中的具体事物或时刻如何形成联系。例如身体和手中手机的方向与喷发同时可见；不从背影猜眼神或表情。 |

两名独立评委先仅看匿名照片和目标，冻结自己的等级及位置依据，不看模型、平台或另一位评委。第二阶段把两个版本的证据随机混排，去掉模型名、等级和版本；先标「可定位 / 仅泛描述 / 看不出」，再标是否足以说明额外效果。证据来源与照片的对应关系由操作者保存。每个「照片 × 维度」独立记录，正反序是重复测量，不算两个独立样本。分歧保留，不移出覆盖率分母。

### 证据评审须消除语言线索

本次回放中，仅凭有无汉字就能把 80 条维度证据按实验组分开。只删版本名、等级再打乱并不构成盲评。原始响应不改，产品的简体中文遵从情况按原始响应另报；汉字检查可提示全英文回归，不能据此证明译文是流畅的简体中文，也不把该检查加入评分 JSON 的硬校验。

1. 操作者抽取原始位置与依据，保存其对应关系；给统一表述人员的材料只含一次性随机编号和两段文本，不给照片、拍摄目标、等级、模型、版本或成对关系。
2. 两组统一为简体中文，原本已清晰的中文不扩写。保留原来指的区域、对象、相互关系、程度、歧义与不确定性；不补画面里实际上存在但模型没说过的细节。例如 “center” 只能写「画面中央」，不能补「中央右侧的手机和手」。采用同一格式和处理流程，未通过忠实度抽查的条目不单边删除或补写。
3. 在发给评委前锁定原文与展示文本的映射，统一字段格式后再随机排序。无法验证统一表述忠实、发现仍可从措辞推断版本，或直接展示双语原文时，标记证据比较为探索性，不据此给候选晋级；报告受影响条数。独立评委在看到证据前已经提交的照片等级保持不变。

分别报告：已共识的「仅 3」被错误给 4 的比例；已共识的「可支持 4」被保留的比例；证据可定位率；换序时分档/具体锚点是否改变；简体中文要求、无效/弃权、意图与平局是否回归。不能凭减少 4 或强行拉开 A/B 晋级。过开发校准后才冻结版本进入留出；即使过留出也仍须单独做指导重拍。

### 两位评委的参考分覆盖

以「一张照片 × 一个维度」为计数单位。两个独立评分都为 3 且有位置及依据才是参考 3；两个都为 4 且各有位置、依据及额外效果说明才进入待核实参考 4。先检查证据实际能定位且支持该效果，程序只检查字段有无，不能替人验证。相同的 0、1 或 2 单报。3/4 或 4/3 是本实验最关键的分界争议，**不平均、不四舍五入**；其他分歧、不可判断/缺失、证据不足分别保留。报告每维有效参照 3 和 4 的独立分母；没有某一等级的参照，写「无参照」，不是 0% 或 100%。第三位评委最终即使给出结论，也保留最初分歧。模型换序不增加独立样本数。

[离线清点脚本](../../scripts/tally_aesthetic_anchors.py) 接受私有锁定名单和两份原始 CSV，仅输出每维覆盖计数，不输出照片来源、评委 ID、观点或评分晋级。操作者需确认两份票确实来自两位独立评委，保持原始 CSV 与图片字节不变；不同 ID 本身并不证明独立。三图探索包的每维上限是三，不用于泛化或正式阈值。空白表试跑每维为 3 条待定、0 人评，并未产生虚假参考等级。Windows 离线 **56/56**，含两票取值的 36 种组合测试。
