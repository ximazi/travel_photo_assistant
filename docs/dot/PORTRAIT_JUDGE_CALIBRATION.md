# 多模型人像盲评：执行与调优 v0.2

关联 #31。产品目标和五维权重沿用 [评分体系](PHOTO_QUALITY_BENCHMARK.md)。本版新增可执行评委提示词和核验器，**不是已经通过真图校准的评委**。

## 一、明确判定

- 评委按 [完整系统提示词](../../assets/prompts/portrait_quality_review.system.txt) 的五个 0–4 锚点逐项评分，每项附区域与看得见的依据；无法判断填 null。分值不是概率。
- 美感：`Σ(权重 × 单项 / 4)`，五项齐全才有总分。两张相差 **≤5 分**为平，缺证据为不确定；5 分是开发阶段待校准的实用起点，不是统计显著性阈值。
- 意图：0 明确失败，1 部分满足，2 满足，null 不确定。任一硬要求明确未满足即 0。美感、意图分别比较，不合成为总冠军；例如更美的 A 未保留灯塔，仍可判 B 更符合需求。
- 本比较仅用于真实旅行人像，不给空景、人形框或合成效果图冒充成片打分。无人取景与站位仍使用原有分开的实验。二维数值不能证明取景更安全、建议可执行或指导改善实拍。

## 二、发给每个模型的实际请求

把系统提示词文件全文作为 system（若界面只给一个输入框，先贴全文，再贴请求）。同一对图片在独立新请求里按顺序附两张，消息只写：

```text
intent: {"goal":"竖版旅行纪念照，人物为主体","required_elements":["保留可辨认的灯塔","人物全身入镜"]}
附件顺序：第一张为 A，第二张为 B。
```

返程交换附件顺序，意图字节不变。不给参考答案、其它评委结果或平台信息；去 EXIF、统一呈现尺寸和匿名命名，不做会改取景的裁切。若平台自动预处理，记录差异；若模型或 UI 改版，另记为一条评审路线，不与历史得分混算。锁定同批图片哈希、版本、提供方、传参、日期、请求顺序、重试策略与权限，避免只留下成功结果。

## 三、实际对比设计

| 角色 | 规则 |
|---|---|
| 人工参考 | 独立双人盲评，分歧复核。保留原票、平票和不确定。人的“更愿意留下哪一张”独立投票，不用机器公式替代人评。 |
| Gemini | 已配置的免费路线，仅处理现有授权范围内的样本；能否发送人像按单张权限记录，不从公开链接推定。 |
| 第二、第三评委 | 各使用不同模型家族的视觉模型，例如 OpenAI 视觉评委与本地开源视觉评委。先验证实际可用性、版本、处理范围、不计费约束；没有合格路线就标未运行。不同提示词或同家族换型号不算独立家族。 |
| 顺序 | 每位模型、每对照片都独立跑 A/B 和 B/A（预先随机化哪个先发）；解析后归回原图。单次无效、两顺序意见不一致均不可推荐。显式弃权有效但不算决定性覆盖。 |

输入留私有目录；提交代码和匿名汇总，不提交样片、来源账号或原始人像。离线脚本不联网，也不读取图片、密钥或调用模型。每一行来自已经收集的 JSON 回执，缺失的回执用 null 或省略，不补造：

```json
{
  "model_ids": ["provider/model-version-a", "local/model-version-b"],
  "pairs": [{
    "pair_id": "opaque-01",
    "scene": "coast",
    "requirement_count": 2,
    "human": {"beauty":"tie","intent":"A"},
    "models": {
      "provider/model-version-a": {
        "forward":{"status":"abstain","reason":"图片不可判读"},
        "reverse":null
      }
    }
  }]
}
```

运行 `python scripts/compare_portrait_judges.py <private-batch.json>`。输出按模型、场景、审美/意图分别统计，附每对归一后的模型票；可定位模型互相冲突和所有模型一致但偏离人的案例。使用 `matches_human / human_decided_model_covered` 和 `matches_human / human_decided` 分别看选择质量和实际有效命中；覆盖为 `human_decided_model_covered / human_decided`。看 `swap_stable / both_valid` 时同时公布失败数、弃权数、稳定选出 A/B 的数（`stable_model_picks`）和稳定判平的数（`stable_model_ties`）。另报人有明确 A/B 偏好时的选片覆盖 `human_pick_model_picked / human_picks`、选对比例 `matches_human_picks / human_picks`、误判平率 `human_pick_model_tied / human_picks`，以及人判平时模型硬选次数和正确判平次数。分母为零表示不适用。总是判平可能让换序稳定和普通覆盖达到 100%，不等于会选片；正确的人类平票仍计入一致。不因多数投票而把模型判断写成真值。理由文本能解析不代表像素依据是真的，仍需人工抽核。

## 四、怎么根据分歧调优

1. 在 10 对开发样本上对每次分歧做人工复盘，编码为：漏看/幻觉、规则锚点模糊、重复扣分、用户需求误解、平票边界过松/紧、左右偏置、结构/输入错误、人与人风格差异。改一条规则或一个示例后原样复跑所有可用家族，比较旧/新，不能只优化 Gemini。
2. 冻结提示词、阈值、人工标签规则和模型标识后，用 20 对独立留出比对；不看留出来调权重。报告逐场景人工一致、模型一致和覆盖、换序、平票误推与分歧案例，再决定哪个模型能当候选评委。工程门槛见总协议；不同模型都猜错时回到画面与人评。
3. 优先修正硬需求误判和幻觉，再改善审美一致。如果留出失败，只能回开发集修正，再拿新的留出复验，不覆写旧结论。下一阶段才做同场真实指导重拍比较。

当前证据：10 项 Windows 离线契约测试，覆盖排序矛盾、数值类型、硬要求、未知维度、平票及换序偏置；模型回执为测试构造，不代表任何真实模型表现。本次统计变更没有新模型调用；首次实图开发对照另见 [DEV-01](PORTRAIT_JUDGE_DEV01_CANYON.md)，仍未完成人工留出盲评。
